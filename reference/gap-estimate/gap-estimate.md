## f、g 的 AE solo 重叠估算

端到端时间等于 AE solo 加整 kernel 融合窗口 E2E 记录中的 VLM kernel 执行时长之和，再减去 VLM 可在 AE 期间完成的时间。使用回退版本实跑的 AE solo 切片，step 0 / layer 0 重复 180 次。AE 总长已经包含搬入、读出、Q 交换及 AE GPU 块。

## 口径与局限

- 只计 DQ，忽略 CA 争用和 rank0 行冲突。GPU 仅使用空隙，PIM 时间线固定，相当于理想的 pim_head。
- 每单元均采用 memory-bound 流体速率。PIM 占用时间按 1:1 计入损失。VLM 损失在活跃 PIM stage 内按 T 减 16 通道平均 ΣU 计算，AE GPU 块暂停 VLM，等待时间为零。
- 写不能超前于读。实际 kernel 的读写交替形状未建模。单元在最慢通道完成时结束，其它通道在同一空隙内可以等到该时刻继续下一单元。
- α 只缩放代理写请求，按原生输入约定向上取整到 sector，随后将请求平均分给 16 通道。每个 α 都从 profile 时长重新计算每条请求的 CK。
- same_first 无历史时优先读，best 的入口成本相同时沿用 same_first。random 按剩余读写比例抽样，条件是两个方向当前均可发。表中 random 为固定种子样本均值，JSON 记录种子、样本和 total 的标准误。
- 每个空隙先假设尾方向等于入口方向，最多重新计算两次右边开销。仍不收敛时预留两方向中较大的右边开销，JSON 按阶段记录次数。ΣU 是可用容量，逐空隙表另列实际发射的读写数，起止 CK 相对各自 stage 的起点。
- DQ 估算把独立启动的单层 AE solo 时间线重复 180 次。层外 AE GPU 块和跨层 DRAM 状态延续未进入该模型。g 的代表性对照用两个实跑 AE solo 切片分别重复 180 次。
